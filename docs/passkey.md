# 通行证（Passkey）登录

用指纹、人脸、PIN、Windows Hello 或密码管理器（Bitwarden、1Password 等）里的通行证登录面板，浏览器里不用再存访问密钥。

## 前提

- 面板要用 **HTTPS 域名** 或 **localhost** 打开。用 `http://IP:端口` 打开时浏览器不允许使用通行证。
- 通行证和域名绑定：在 `ovh.example.com` 添加的，只能在 `ovh.example.com` 登录。换了域名需要重新添加。

## 添加

1. 先用访问密钥登录。
2. 设置 → 访问密码 → 添加通行证，起个名字，再输一次访问密钥，然后按系统提示验证。

添加时要再输一次访问密钥，是为了防止拿到你登录状态的人偷偷给自己加一个通行证。

## 登录与退出

- 登录页点「使用通行证登录」。登录状态保持 30 天。
- 设置 → 访问密码 → 退出登录：服务器端同时作废这次登录。
- 删除一个通行证，用它登录的浏览器会立即退出。

## 关闭访问密钥登录

设置 → 访问密码 → 关闭访问密钥登录。打开后网页只能用通行证登录，访问密钥只用于添加通行证、查看完整凭据这类二次确认。App 设备令牌和 Telegram 不受影响。

为了防止把自己锁在外面，只有**当前用通行证登录**的浏览器才能打开这个开关。

## 通行证都用不了时怎么找回

在服务器的数据目录里创建一个名为 `allow-key-login` 的文件（内容随意），访问密钥登录会在几秒内恢复，不需要重启：

```bash
# Docker 部署：compose 文件旁边的 data 目录
touch ./data/allow-key-login

# 单二进制部署：DATA_DIR 指向的目录（没设的话是启动时工作目录下的 data）
touch /path/to/data/allow-key-login
```

用访问密钥登录后，重新添加通行证，或者在设置里把「关闭访问密钥登录」关掉，然后**删除这个文件**。文件存在期间，设置页会一直提示。

能在服务器上创建文件的人本来就能完全控制这台机器，所以这个找回方法不会降低安全性。

## 什么情况下通行证会失效

- **更换了 `API_SECRET_KEY`**：所有通行证和登录状态一起失效，在设置里会标成「已失效」，删掉后重新添加即可。怀疑访问密钥泄漏时换掉它，别人偷偷加的通行证也会一起作废。
- 在另一个域名下打开面板（见「前提」）。

## 密码管理器保存时要手动选位置（Bitwarden 等）

Bitwarden 保存通行证时，会把网址与当前网站匹配的已有登录项都列出来让你选存进哪一个。它默认按主域名匹配，`a.example.com` 和 `b.example.com` 会被当成同一个网站，所以会出现一串不相关的项目。

- 保存时直接选「新建项目」；或者
- 在 Bitwarden 里把这些登录项的「URI 匹配检测」改成「主机」。

通行证的用户名是 `admin@你的域名`，在列表里可以认出来。

## 关于「App 配对」

设置里的「App 配对」是给配套手机 App 用的：App 扫码后拿到一个独立的设备令牌，丢了手机可以单独吊销。这个 App 目前没有公开发布，所以只有已经配对过设备时，设置里才会显示这一项。
